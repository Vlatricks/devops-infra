# Архитектурное решение (LADR): Выбор системы мониторинга

## Статус
Принято (Accepted)

## Контекст
Для обеспечения надежности платформы `instahelper.com` необходимо развернуть систему мониторинга. Система должна собирать метрики операционной системы серверов (CPU, RAM, Disk) и метрики самого приложения, а также визуализировать их на дашбордах по разным окружениям.

## Решение
Выбран стек **Prometheus** и **Grafana** по следующим причинам:
1. **Prometheus** использует Pull-модель сбора метрик, что идеально подходит для нашей Docker-инфраструктуры, и имеет встроенную интеграцию со многими экспортерами.
2. Для сбора системных метрик серверов будет использоваться **Node Exporter**.
3. **Grafana** является индустриальным стандартом для построения дашбордов и имеет нативную поддержку Prometheus в качестве источника данных (Data Source).

## Последствия
* Требуется развернуть Prometheus и Grafana на выделенном сервере мониторинга, чтобы они не утилизировали ресурсы боевого приложения.
* На серверах приложений необходимо развернуть Node Exporter на порту `9100`.
