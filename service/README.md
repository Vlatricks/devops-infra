# Ansible-код для развёртывания шаблонного сервиса через Systemd

Этот репозиторий содержит Ansible-сценарий для упаковки Docker-контейнера приложения в полноценную системную службу Linux (systemd unit) и управления её жизненным циклом.

## Структура проекта
* `site.yml` — главный плейбук (манифест) для запуска деплоя.
* `tasks/main.yml` — логика копирования шаблона и управления службой systemd.
* `handlers/main.yml` — обработчик (handler) для автоматического перезапуска службы при изменении конфигурации.
* `defaults/main.yml` — переменные по умолчанию (имя сервиса, образ, порты, версия).
* `templates/service.unit.j2` — Jinja2-шаблон systemd unit-файла для Docker.

## Переменные по умолчанию (defaults/main.yml)
Вы можете переопределить эти параметры под любое другое приложение:
* `service_name` — имя службы в системе (например, `skillbox-app`)
* `service_image` — имя Docker-образа (например, `skillbox/app`)
* `service_version` — тег/версия образа (по умолчанию `latest`)
* `service_port` — порт приложения для проброса наружу (например, `8080`)

## Инструкция по использованию

Для запуска деплоя сервиса на целевых хостах выполните команду:

```bash
ansible-playbook site.yml
```

### Смена версии Docker-образа при деплое
Чтобы обновить или изменить версию Docker-образа прямо во время деплоя (например, в CI/CD пайплайне), передайте переменную `service_version` через флаг `--extra-vars`:

```bash
ansible-playbook site.yml --extra-vars "service_version=v1.2.3"
```

При изменении версии Ansible автоматически обновит конфигурационный файл на сервере, вызовет обработчик `Restart service` для перезагрузки демона systemd, скачает новый Docker-образ и перезапустит контейнер.
